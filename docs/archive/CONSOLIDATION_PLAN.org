* Vision

Consolidate the proven patterns from ~nostr-feeds~ into Tendrl, using nostrdb for efficiency while maintaining the config-driven, modular architecture that works.

**Goal**: One unified system with:
- ✓ nostrdb's speed and efficiency (LMDB, native Rust)
- ✓ nostr-feeds' proven patterns (config-driven, modular)
- ✓ Notedeck integration for UI
- ✓ Jinja2 rendering for flexibility

* Current State

** nostr-feeds (Mature)
- 3 years production use
- Config-driven architecture
- nak + SQLite + Jinja2
- Multiple output formats (text, HTML, SPA, JSON API)
- Proven enrichment algorithms
- ~33 Python modules

** Tendrl (Evolving)
- nostrdb + notedeck integration
- TOML-driven feed definitions (~tendrl.toml~)
- Rust query engine (~tendrl_query~)
- Feed injection for Notedeck
- Has tag value bug (blocking)

* Phase 1: Create Query Abstraction Layer

Create a Python interface that can work with either backend:

#+begin_src python
# tendrl/query_backend.py

from abc import ABC, abstractmethod
from typing import List, Dict, Optional

class QueryBackend(ABC):
    """Abstract interface for event queries"""

    @abstractmethod
    def query_events(self, kinds: List[int], authors: Optional[List[str]] = None,
                     limit: int = 100, since: Optional[int] = None,
                     until: Optional[int] = None) -> List[Dict]:
        """Query events with filters"""
        pass

    @abstractmethod
    def get_event_by_id(self, event_id: str) -> Optional[Dict]:
        """Get single event by ID"""
        pass

    @abstractmethod
    def get_events_by_tag(self, kind: int, tag_type: str,
                          tag_value: str, limit: int = 100) -> List[Dict]:
        """Query events by tag reference"""
        pass


class NostrdbBackend(QueryBackend):
    """Backend using nostrdb (fast, when working)"""

    def __init__(self, db_path: str, config_path: str):
        self.db_path = db_path
        self.config_path = config_path

    def query_events(self, kinds, authors=None, limit=100, since=None, until=None):
        # Use tendrl_query binary
        cmd = ['./tendrl/target/release/tendrl_query',
               '--config', self.config_path,
               '--kinds', ','.join(map(str, kinds)),
               '--limit', str(limit)]

        if authors:
            for author in authors:
                cmd.extend(['--author', author])

        result = subprocess.run(cmd, capture_output=True, text=True)
        return [json.loads(line) for line in result.stdout.strip().split('\n') if line]


class SqliteBackend(QueryBackend):
    """Backend using SQLite (proven, reliable)"""

    def __init__(self, db_path: str):
        self.conn = sqlite3.connect(db_path)
        self.conn.row_factory = sqlite3.Row

    def query_events(self, kinds, authors=None, limit=100, since=None, until=None):
        # Use nostr-feeds proven query logic
        query = "SELECT * FROM events WHERE kind IN ({})".format(
            ','.join('?' * len(kinds))
        )
        params = list(kinds)

        if authors:
            query += " AND pubkey IN ({})".format(','.join('?' * len(authors)))
            params.extend(authors)

        if since:
            query += " AND created_at >= ?"
            params.append(since)

        if until:
            query += " AND created_at <= ?"
            params.append(until)

        query += " ORDER BY created_at DESC LIMIT ?"
        params.append(limit)

        cursor = self.conn.execute(query, params)
        return [self._parse_row(row) for row in cursor.fetchall()]

    def _parse_row(self, row):
        event = dict(row)
        if 'tags_json' in event and event['tags_json']:
            event['tags'] = json.loads(event['tags_json'])
        return event
#+end_src

if config.database.backend == "nostrdb":
    try:
        backend = NostrdbBackend(config.database.nostrdb_path)

* Why This Approach Works

1. **Incremental Migration**: Start with proven SQLite, migrate to nostrdb when ready
2. **Backend Abstraction**: Code doesn't care which database is used
3. **Best of Both**: Keep nostr-feeds' algorithms, add nostrdb's speed
4. **Unblocks Progress**: Don't wait for bug fix to make progress
5. **Risk Mitigation**: Always have SQLite fallback
